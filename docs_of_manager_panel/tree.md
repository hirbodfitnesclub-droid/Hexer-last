## ۲. توصیف دقیق و کاربردی هر فایل (File-by-File Catalog Specification)

### ۲.۱. فایل‌های پیکربندی ریشه پروژه (Root Configurations)

| مسیر فایل | وظیفه و محتوای فنی فایل |
|---|---|
| `/.env.example` | مستندسازی متغیرهای محیطی مورد نیاز برنامه به همراه کلیدهای فرضی سلف‌کانتین مانند `VITE_SUPABASE_URL` و `VITE_SUPABASE_ANON_KEY` بدون افشای سکرت‌های تولید. |
| `/.gitignore` | ممانعت از ارسال فولدرهای خروجی بیلد تفکیک شده دایرکتوری (`dist/`)، مدیریت وابستگی‌ها (`node_modules/`)، لاگ‌های خطای ران‌تایم و اطلاعات حساس سشن یا متغیرهای محیطی محلی به مخزن گیت. |
| `/index.html` | نقطه شروع کلاینت تک‌صفحه‌ای (SPA)؛ بارگذاری المان والد هکسر با شناسه اتمیک `id="root"`، متای راست‌چین (RTL) و ارجاع پیوند به اسکریپت اصلی فرانت یعنی `/src/main.tsx`. |
| `/metadata.json` | شامل تعاملات و مشخصات اپلت پلتفرم هوش مصنوعی استودیو؛ مانند مجوزها (Permissions) و قابلیت‌های پیشرفته مانند `MAJOR_CAPABILITY_SERVER_SIDE_GEMINI_API`. |
| `/package.json` | مدیریت وابستگی‌ها و کدهای کامپایل فرانت؛ نسخه وابستگی‌های کلیدی شامل React 19، Zustand v5، Tailwind CLI v4، Recharts v3، Framer Motion و کتابخانه کلاینت `@supabase/supabase-js`. شامل دستور اسکریپتِ `npm run dev` با تنظیم اتصال پورتی پایدار روی ۳۰۰۰. |
| `/package-lock.json` | قفل کردن کاتالوگ جزییات درایورها، کتابخانه‌ها و وابستگی‌های تابعه برای هماهنگی فرآیند نصب. |
| `/tsconfig.json` | کانفیگ تایپ اسکریپت؛ تعیین قوانین نوع‌دهی، کامپایل ماژول‌های ES و تضمین الگوهای مدرن خنثی‌کننده خطاها (Strict Type Checking). |
| `/vite.config.ts` | پیکربندی بیلد سه‌سوته با Vite؛ تعریف پلاگین کلاینت React و استیک لایه پورت ۳۰۰۰ به همرسی محلی آدرس لوکال‌هاست جهت تسهیل آی‌فریم. |

### ۲.۲. فایل‌های مستندات و لنگرگاه‌های طراحی (Project Docs / Project Brain)

| مسیر فایل | وظیفه و محتوای فنی فایل |
|---|---|
| `/docs/PROJECT.md` | **ستاره قطبی پروژه**؛ تعریف اهداف کسب‌وکار برای پنل مدیریت هکسر، پشته تکنولوژی انتخاب شده، پایش ریشه‌ای خطاهای تاریخی در سکرت‌ها و اعلام باطل‌شدن کلیدهای مرورگر در ساختارهای سوپابیس، و دارای بخش **نبایدهای سخت‌گیرانه (Anti-Patterns)** که مدل کدنویس باید بی‌چون‌وچرا از آن‌ها تبعیت کند. |
| `/docs/ARCHITECTURE.md` | **لنگرگاه معماری سیستم**؛ مپینگ عدم‌تطابق داده‌های بومی دیتابیس با واسط‌های گرافیکی فرانت (Anti-Corruption Layer) در قالب DTOها، تشریح مسیردهی RPC در گیت‌وی ادمین و قرارداد اکشن‌های تابع Edge Function. |
| `/docs/tasks.md` | **نقشه راه توسعه متوالی**؛ تعریف زنجیره‌ای از کارهای متوالی با شماره TASK، توصیف دقیق کلاینت، فایل‌های کانتکست ذیربط و محدودیت‌های پیاده‌سازی جهت جلوگیری از تداخل موازی کاتالوگ فرانت و سرور. |
| `/docs/CURRENT_TASK.md` | **دستور کار عملیاتی جلسه جاری**؛ شامل جزییات عمیق برای انجام تسک سوم و چهارم نقشه راه (اتصال به دیتابیس از طریق Gateway و رفع باگ‌های جزئی ریچارتز و کوپن‌های فرمت نامعتبر). |

### ۲.۳. ساختار عصبی لایه کلاینت (Application Entrypoint & Global CSS)

| مسیر فایل | وظیفه و محتوای فنی فایل |
|---|---|
| `/src/main.tsx` | باندلر نقطه اجرای سمت کاربر؛ مانت کردن المان مادر `<App />` در DOM با فعال بودن StrictMode فریمورک React. |
| `/src/App.tsx` | روتر مرکزی سیستم؛ فراخوانی Zustand استور جهت احراز هویت ادمین. اگر ادمین تایید شده باشد دایرکتوری `<AdminLayout>` را به همراه تب فعال رندر می‌کند و در غیر این صورت گیت عبور `<Login />` را فعال می‌کند. حاوی توستر راست‌چین `'react-hot-toast'` تزیین شده با فونت وزیرمتن. |
| `/src/index.css` | پرونده اصلی استایل پروژه؛ فرخوانی توابع جدید Tailwind v4 با `@import "tailwindcss";`، نصب فونت وب «وزیرمتن» از آدرس وب فونت زنده گوگل، و تعریف توکن‌های رنگی و فونت سانز و مونو در بلاک اختصاصی `@theme`. |

### ۲.۴. لایه پایدار ایزوله‌ساز وب (Frontend Data Services & Supabase Interfaces)

| مسیر فایل | وظیفه و محتوای فنی فایل |
|---|---|
| `/src/lib/supabase.ts` | **تضمین انسجام تایپ‌ها**؛ تعریف کلاس‌ها و اینترفیس‌های مشترکی چون `Profile` (شامل نمایش فیلدهای ایمیل و بلاک موقت)، `Subscription`، `Plan`، `Payment` و `DiscountCode`. کلاینت اصلی سوپابیس سمت کاربر در این فایل منحصراً با کلید عمومی (anon key) لود می‌شود و ایمن از سکرت است. |
| `/src/lib/dataStore.ts` | **پوسته هوشمند انتقال داده**؛ کپسوله‌ساز تمام متدهای مورد نیاز صفحات. به جای فرستادن کوئری به REST مستقیم سوپابیس، با ارسال درخواست‌های `POST` به آدرس Edge Function گیت‌وی یعنی `admin-api` بازیگرانِ اتمیک لایه کلاینت را به RPC سرور متصل می‌کند. هدرهای سکرت ساده `x-admin-secret` را ضمیمه بدنه می‌کند. |

| `/supabase/functions/admin-api/index.ts` | **گیت‌وی همه‌کاره و فوق‌امن ادمین**؛ با دور زدن لایه امنیتی هارد ادمین سوپابیس (Bypassing RLS tables via createClient with Service Role Key)، عملیات‌های Privileged لایه ادمین را اجرا می‌کند. از طریق متد RPC با فیلد `action` کار می‌کند. فچ‌های سنگینی چون لیست کاربران، آپدیت سشن بلاک با Admin API سوپابیس، لیست تراکنش‌ها، عضویت‌های و تخفیف‌ها را سمت سرور با هم ادغام (Join) کرده و اطلاعات را تمیز و سریع به فرانت بفرستد. از طریق هدر `x-admin-secret` با مقدار متغیر امنیتی `ADMIN_API_SECRET` از هرگونه فرورفت هکرها در امان است. |

## ۳. ویژگی‌های اساسی فرانت برای درک راحت معمار

- **دقت در مسیر ادمین**: تمام کارهای عملیاتی ادمین تنها با تکیه بر متدهای کلاس `dataStore` در `/src/lib/dataStore.ts` سازمان‌دهی شده که این متدها کاملاً منطبق بر ساختار پاسخ گیت‌وی `admin-api` هستند.
- **تضمین سلامت هماهنگی**: رابط کاربری فرانت به شدت ماژولار است؛ تمام کامپوننت‌های بزرگ به مودال‌ها و ردیف‌های اتمیک تابعه خرد شده‌اند تا از تداخل کدها ممانعت شده و ظرفیت کانتکست در بیلد گم نشود.
- **راست‌چین اصیل (Persian Native RTL)**: تمام بخش‌ها با کلاس‌های قدرتمند Tailwind v4 به شکل بومی راست‌چین طراحی شده‌اند و هماهنگ با تقویم خورشیدی و سیستم ممیزگذاری ریالی کار می‌کنند.
