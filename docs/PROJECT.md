## ۱. هدف بیزینس
«هکسر» یک **دستیار بهره‌وری شخصی مبتنی بر هوش مصنوعی و کاملاً فارسی (RTL)** است که با تبدیل گفتار، تصویر و متنِ کاربر به آیتم‌های ساختاریافته (کار، یادداشت، پروژه، عادت) و یادآوریِ هوشمند آن‌ها، بار ذهنی کاربر را حذف می‌کند.
مدل درآمدی: **اشتراک ماهانه سه‌سطحی (Freemium → Plus → Pro)** از طریق درگاه پرداخت ایرانی **زیبال**.

## ۲. پرسونای هدف
- کاربر فارسی‌زبان حرفه‌ای، فریلنسر، دانشجو یا مدیر کوچک که حجم بالایی از تسک/ایده دارد.
- ترجیح می‌دهد به‌جای تایپ، با **صدا یا اسکرین‌شات** ورودی بدهد و سیستم خودش آن را به تسک تبدیل کند.
- غیرفنی است؛ هیچ مفهوم فنی (دیتابیس، توکن، RLS) نباید به او نشت کند. تجربه باید بی‌نقص و «جادویی» باشد.

## ۳. پشته تکنولوژی (Tech Stack)
> این پشته **تثبیت‌شده** است. هر درخواستی که با آن در تضاد باشد باید با همین پشته تطبیق داده شود، نه برعکس.

| لایه | تکنولوژی | نکته |
|------|----------|------|
| فرانت‌اند | **React 19 + TypeScript** | کامپوننت‌های تابعی + Hooks |
| بیلد/دِو | **Vite 6** | importmap + alias `@` |
| استایل | **Tailwind CSS (CDN)** | RTL، فونت `Vazirmatn`، تم تیره (`gray-950`) |
| بک‌اند | **Supabase** | Postgres + Auth + Storage + Edge Functions + Realtime |
| جستجوی معنایی | **pgvector** | امبدینگ ۷۶۸ بُعدی (`text-embedding-004`) |
| هوش مصنوعی | **Google Gemini** (`@google/genai`) | مدل بر اساس پلن کاربر تعیین می‌شود |
| پرداخت | **درگاه زیبال (Zibal)** | از طریق Edge Functions، تأیید سمت سرور |
| اجرای کد بک‌اند | **پنل آنلاین Supabase** | اجرای دستی SQL و آپلود دستی توابع |

## ۴. محیط عملیاتی (قانون اجرای بک‌اند)
- تمام کد بک‌اند فقط به‌صورت **فایل‌های خام و ماژولار** در سورس‌کد محلی تولید می‌شود:
  - SQL در `supabase/sql/` (فایل‌های شماره‌دار و **Idempotent**).
  - توابع لبه در `supabase/functions/<name>/index.ts`.
- کاربر این فایل‌ها را **دستی** در پنل آنلاین Supabase اجرا/آپلود می‌کند.
- **ممنوع:** هیچ تسکی نباید به اجرای دستورات `supabase` CLI (مثل `db push`, `functions deploy`, `migration`) متکی باشد.

## ۵. [حیاتی] نبایدهای سخت‌گیرانه (Anti-Patterns)
> مدل کدنویس باید بی‌چون‌وچرا از این لیست اطاعت کند. تخطی از این موارد = خروجی مردود.

### امنیت داده
1. **ممنوعیت داده بدون مالک:** هیچ جدولِ حاوی داده کاربر بدون `user_id` و بدون **RLS فعال** ساخته نمی‌شود. RLS هر جدول باید روی `auth.uid() = user_id` قفل شود.
2. **ممنوعیت `service_role` در کلاینت:** کلید `service_role` فقط داخل Edge Functions و فقط از `Deno.env` خوانده می‌شود. هرگز در فرانت‌اند، importmap یا فایل‌های `services/` ظاهر نمی‌شود.
3. **ممنوعیت اعتماد به کلاینت برای منطق پولی:** وضعیت اشتراک، سقف مصرف و فعال‌سازی پلن **فقط سمت سرور** (RPC/Edge) اعمال می‌شود. کلاینت فقط نمایش می‌دهد.
4. **ممنوعیت اعتماد به Callback پرداخت:** نتیجه پرداخت زیبال فقط با فراخوانی **Verify سمت سرور** نهایی می‌شود؛ هرگز بر اساس پارامترهای بازگشتیِ مرورگر، اشتراک فعال نمی‌شود.

### مدیا و انتقال داده
5. **ممنوعیت کامل Base64 برای مدیا:** ارسال صوت/تصویر به‌صورت Base64 از کلاینت به Edge Function **به‌طور کامل حذف** می‌شود. مسیر مجاز: آپلود به **Supabase Storage** → ارسال فقط **مسیر/URL** فایل.
6. **باکت‌های مدیا همیشه Private** هستند و دسترسی فقط با Signed URL یا Service Role داخل تابع.

### یکپارچگی داده
7. **ممنوعیت نوشتنِ چندمرحله‌ایِ کلاینت:** عملیات اتمیک (مثل ساخت تسک + چک‌لیست، یا فعال‌سازی پلن + ریست مصرف) فقط داخل **یک تابع RPC** انجام می‌شود تا Race Condition رخ ندهد. الگوی فعلی «insert سپس update جداگانه» در `taskService.createTask` باید حذف شود.
8. **پول همیشه عدد صحیح:** مبالغ به **ریال/تومان به‌صورت `bigint`** ذخیره می‌شوند؛ استفاده از `float`/`numeric` برای پول ممنوع است.

### Realtime
9. **ممنوعیت اشتراک‌های فیلترنشده:** هر `supabase.channel(...).on('postgres_changes', ...)` **باید** با `filter: 'user_id=eq.<UID>'` محدود شود. الگوی فعلی (گوش‌دادن به کل جدول) ممنوع است.

### معماری کد
10. **ممنوعیت ORM:** اتصال به دیتابیس فقط با کلاینت رسمی `@supabase/supabase-js`. استفاده از Prisma/Drizzle/TypeORM ممنوع است.
11. **ممنوعیت `localStorage` برای داده دائمی:** منبع حقیقتِ داده، Postgres است. `localStorage` فقط برای تنظیمات گذرای UI مجاز است.
12. **ممنوعیت SQL غیر-Idempotent:** هر فایل SQL باید چندبار قابل اجرا باشد (`CREATE ... IF NOT EXISTS`, `DROP POLICY IF EXISTS` قبل از `CREATE POLICY`, `CREATE OR REPLACE FUNCTION`).
13. **ممنوعیت Secret هاردکد:** کلیدها فقط از env (Vite env در کلاینت، `Deno.env` در توابع). مقادیر هاردکدِ فعلی در `services/supabaseClient.ts` باید به env منتقل شوند.

### تجربه کاربری
14. **ممنوعیت کرش بی‌صدا:** هیچ خطای شبکه/تایم‌اوت/قطع‌بودن اینترنت نباید باعث کرش یا صفحه سفید شود. همه باید با UX افت تدریجی (Graceful Degradation) و پیام فارسی مدیریت شوند.
15. **هیچ ایموجی به‌عنوان آیکن:** فقط از کامپوننت‌های آیکن موجود در `components/icons.tsx` استفاده شود.

## ۶. تعریف «آماده انتشار» (Definition of Done)
یک قابلیت زمانی Production-Ready است که: ۱) RLS آن تست شده و کاربر دیگری به داده دسترسی ندارد، ۲) خطاها و حالت آفلاین گرِیس‌فول مدیریت شده‌اند، ۳) منطق پولی/مصرفی سمت سرور قفل است، ۴) فایل‌های SQL/تابع آن ماژولار و Idempotent و آماده اجرای دستی در پنل هستند.
