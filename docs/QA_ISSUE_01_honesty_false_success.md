## ۱. مشکل چیست؟ (به زبان ساده)

کاربر یک جمله‌ی عادی فارسی می‌گوید، مثلاً:

> «یه تسک دارم؛ گرفتن کاوه نگار برای پاناچت. باید به پروژه پانافر وصل بشه و برای امروز هم هست»

ربات جواب می‌دهد:

> «حتما! تسک 'گرفتن کاوه نگار برای پاناچت' **با موفقیت** برای امروز در پروژه پانافر **ایجاد شد**»

ولی در واقعیت **هیچ تسکی ساخته نشده است.** کاربر باور می‌کند کار انجام شده و بعداً متوجه می‌شود تسک در لیستش نیست. این دقیقاً نقض قول اصلی محصول است: «مدل هرگز نمی‌گوید انجام شد مگر واقعاً در دیتابیس ثبت شده باشد.»

این باگ در production فعال است و **حداقل ۵ بار برای کاربران واقعی اتفاق افتاده** (19، 22 و دو بار در 23 اوت 2026).

**شدیدترین نمونه (23 اوت ساعت 09:26):**
> کاربر: «یه تسک بزن برای فردا، واریز پول مکمل»
> ربات: «تسک «واریز پول مکمل» برای فردا ... با موفقیت ثبت شد.»
> کاربر: «**چرا الکی میگی هیچ تسکی ساخته نشده که**»
> ربات: عذرخواهی + قول ثبت مجدد → دفعه‌ی دوم هم همان باگ تکرار شد.

نکته‌ی فنی جالب: «بزن» در لیست سیگنال‌های classifier نیست — «یه یادآور بزن» به‌خاطر کلمه‌ی «یادآور» create می‌شود ولی «یه تسک بزن» chat می‌ماند. یعنی حتی الگوهای پرتکرار محاوره‌ای پوشش داده نشده‌اند.

## ۲. چطور به این مشکل رسیدم؟

مسیر کشف، مرحله‌به‌مرحله:

1. **باندل deployed را از production گرفتم** و با repo مقایسه کردم → نسخه‌ی v75 سالم است (۲۰/۲۰ فایل بایت‌به‌بایت یکسان). پس مشکل از ناقص‌دیپلوی‌شدن نیست؛ مشکل داخل خود کد است.
2. **جدول audit را خواندم** (`agent_execution_audit`) → دیدم درخواستی با تاریخ 2026-08-22 ساعت 08:13 ثبت شده با این مشخصات مشکوک: `intent='chat'` ولی `rejected_action_count=1`. یعنی مدل دستور ساخت تسک داده ولی سیستم آن را رد کرده.
3. **متن واقعی همان گفتگو را از جدول `chat_messages` درآوردم** → تأیید شد مدل به کاربر گفته «با موفقیت ایجاد شد» در حالی که هیچ action اجرا نشده بود.
4. **همان جمله را روی کد فعلی اجرا کردم** (بدون تماس با سرور یا LLM) → زنجیره‌ی خطا بازتولید شد:
   ```
   جمله → classifyIntent => chat          (اشتباه: باید create می‌شد)
        → action policy => rejected ["intent_chat_disallows"]   (اکشن ساخته نشد)
        → applyHonesty => mode "none"     (گارد honesty خاموش!)
        → پاسخ دروغ بدون تغییر به کاربر رسید
   ```

## ۳. ریشه‌ی مشکل چیست؟

سه ضعف که با هم ترکیب شده‌اند:

### الف) Classifier فقط با «فعل صریح» کار می‌کند
`intent.ts` جمله را با لیست کلیدواژه classify می‌کند («بساز»، «بذار»، «یادآوری»...). جمله‌ی کاربر بالا هیچ‌کدام را ندارد (می‌گوید «یه تسک **دارم**») → می‌افتد روی `chat`.

### ب) گارد honesty خودش به intent معیوب تکیه دارد ⬅️ **حفره‌ی اصلی**
در `applyHonesty` (honesty.ts:63) گارد فقط وقتی روشن می‌شود که intent ∈ {create, mutate} باشد. یعنی وقتی classifier اشتباه می‌کند و intent=chat برمی‌گرداند، **همان اشتباه، safety net را هم غیرفعال می‌کند.** دو لایه‌ای که قرار بود همدیگر را چک کنند، هر دو از یک منبع خطا تغذیه می‌شوند.

### ج) ابزار درست نوشته شده ولی وصل نشده
تابع `looksLikeSuccessClaim` (honesty.ts:34) دقیقاً برای تشخیص ادعای موفقیت ساخته شده، تست هم دارد (۶۳ تست سبز)، ولی **هیچ‌جا در index.ts صدا زده نمی‌شود** — dead code است.

نکته: تست‌های موجود همه سبزند چون هیچ‌کدام سناریوی «جمله‌ی بی‌فعل طبیعی + ادعای دروغ مدل» را ندارند. باگ از وسط test suite رد می‌شود.
